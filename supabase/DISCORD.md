# Discord — пост «Евенти на сьогодні»

Один пост у каналі Discord, який сам оновлюється: новий день — новий список, змінив
евент в адмінці — пост підтягнув зміни за ≤5 хв. Якщо в евента вказаний час — за N хв
до початку в канал прилітає окреме нагадування з пінгом ролі.

Як це влаштовано:

| Шар | Де | Що робить |
|---|---|---|
| Сторінка **«ДС Евенти»** | `/events` (меню зліва) | Список евентів: назва, дні тижня або дата, час, примітка, пінг за N хв, роль. Нові активності потрапляють сюди самі (тригер у БД), далі редагуються незалежно. |
| Таблиці `events`, `discord_event_post`, `discord_event_pings` + функція `events_today()` | `migrations/0005_events_discord.sql` | Дані + «актуальний список на сьогодні» за Києвом. |
| Edge Function **`discord-events`** | `functions/discord-events/index.ts` | API: `GET` — список на сьогодні (JSON); `POST …/sync` — оновити пост у Discord, надіслати пінги, прибрати вчорашні. |
| Крон `discord-events-sync` (pg_cron + pg_net) | та сама міграція | Кожні 5 хв смикає `POST …/sync`. |
| «Події» сервера (Scheduled Events) | та сама функція, потрібен бот | По одній події на кожен евент з часом на 7 днів наперед (крок 6, необов'язково). |

**Для поста й пінгів бот Discord не потрібен.** Усе робить вебхук: він уміє створювати,
редагувати й видаляти свої повідомлення і пінгувати ролі. Бот потрібен лише для
необов'язкового: закріпити пост (крок 5) і вести «Події» сервера (крок 6).

## Крок 1. Міграція

Dashboard → **SQL Editor** → New query → встав увесь `migrations/0005_events_discord.sql` → **Run**.
Потім так само `migrations/0006_stable_sort_order.sql` (стабільний порядок рядків на сторінці)
і `migrations/0007_discord_scheduled_events.sql` (тривалість евента + «Події» Discord).

Міграція ідемпотентна. Якщо впаде рядок `create extension if not exists pg_net`
(або `pg_cron`) — увімкни їх руками через **Database → Extensions** і запусти файл ще раз.

Після цього у меню з'явиться «ДС Евенти» з усіма активностями (без часу — час,
пінг і примітку додаєш там).

## Крок 2. Вебхук Discord

1. **Канал.** Зроби окремий канал, напр. `#евенти`. У правах каналу для `@everyone`
   забери «Надсилати повідомлення» — тоді пост завжди буде єдиним і останнім у каналі.
2. **Вебхук.** Налаштування каналу (шестерня) → **Інтеграції** → **Вебхуки** →
   **Новий вебхук**. Дай ім'я (напр. `Thunder Евенти`) та аватар — так виглядатиме
   автор поста. Натисни **Копіювати URL вебхука**. URL має вигляд
   `https://discord.com/api/webhooks/1234567890/AbCdEf…` — це секрет, не публікуй.
3. **Роль для пінгів** (інакше нагадування йтимуть як `@here`).
   - Налаштування сервера → **Ролі** → створи (напр. `Евенти`) або візьми наявну.
   - У ролі увімкни **«Дозволити всім згадувати цю роль»** — без цього вебхук
     не зможе її пінгнути.
   - Скопіюй ID ролі: Налаштування користувача → **Додатково** → **Режим розробника**
     (увімкни), потім у списку ролей ПКМ по ролі → **Копіювати ID ролі**.
   - Роль можна задати глобально (секрет `DISCORD_PING_ROLE_ID`) і/або окремо для
     евента на сторінці «ДС Евенти» (поле «роль»).
   - Замість ID ролі можна вписати `everyone` — пінг піде як `@everyone` (усі, хто
     бачить канал), або `here` — `@here` (лише ті, хто онлайн). ID сервера теж
     розуміється як `@everyone`.

## Крок 3. Edge Function

Потрібен [Supabase CLI](https://supabase.com/docs/guides/cli): `npm i -g supabase`
(або `brew install supabase/tap/supabase`, або `scoop install supabase`).

```bash
# у корені репозиторію
supabase login
supabase link --project-ref <ref>   # <ref> — із URL проєкту: https://<ref>.supabase.co

# секрети функції (замість значень — свої)
supabase secrets set \
  DISCORD_WEBHOOK_URL="https://discord.com/api/webhooks/…" \
  EVENTS_API_KEY="$(openssl rand -hex 32)" \
  DISCORD_PING_ROLE_ID="123456789012345678"

supabase secrets list                 # перевір, що є всі три

# деплой
supabase functions deploy discord-events --no-verify-jwt
```

- `EVENTS_API_KEY` — твій власний ключ до API (будь-який довгий випадковий рядок;
  без `openssl` — `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`).
  Збережи його: він потрібен для крону (крок 4) і для своїх скриптів.
- `--no-verify-jwt` обов'язково: інакше шлюз Supabase пускатиме лише запити з JWT
  Supabase, а крон і сторонні скрипти ходять із `x-api-key`. Авторизацію функція
  перевіряє сама (ключ або сесія адміна з адмінки).
- Секрети можна задати й через Dashboard → **Edge Functions** → **Secrets**.
  Нові значення функція бачить без повторного деплою.
- **Автодеплой з GitHub.** Воркфлоу `.github/workflows/deploy-functions.yml` сам
  деплоїть функцію при кожному пуші в `main`, що зачіпає `supabase/functions/**`
  (і вручну: Actions → Deploy Edge Functions → Run workflow). Потрібен один секрет
  репозиторію (Settings → Secrets and variables → Actions → New repository secret):
  `SUPABASE_ACCESS_TOKEN` — Supabase Dashboard → аватар → Account → **Access Tokens** →
  Generate new token. `<ref>` проєкту воркфлоу бере з наявного `VITE_SUPABASE_URL`.
  Після цього ручний `supabase functions deploy` більше не потрібен.

Перевірка:

```bash
REF=<ref>; KEY=<EVENTS_API_KEY>

# список на сьогодні
curl -s -H "x-api-key: $KEY" "https://$REF.supabase.co/functions/v1/discord-events"

# створити/оновити пост у Discord прямо зараз
curl -s -X POST -H "x-api-key: $KEY" "https://$REF.supabase.co/functions/v1/discord-events/sync"
```

Після `sync` у каналі має з'явитись пост. Те саме робить кнопка **«Оновити зараз»**
на сторінці «ДС Евенти».

## Крок 4. Автооновлення (крон)

Крон-джоб `discord-events-sync` (кожні 5 хв) уже створений міграцією, але він нічого
не робить, поки не знає URL функції та ключ. Додай їх у Vault — SQL Editor:

```sql
select vault.create_secret('https://<ref>.supabase.co/functions/v1/discord-events/sync', 'discord_events_sync_url');
select vault.create_secret('<EVENTS_API_KEY>', 'discord_events_api_key');
```

Перевірка (через ~5 хв):

```sql
select jobname, schedule, active from cron.job;
select status, return_message, start_time from cron.job_run_details order by start_time desc limit 10;
select status_code, content, created from net._http_response order by created desc limit 5;
```

У `net._http_response` має бути `status_code = 200` і JSON з `"ok":true`.

Хочеш точніші пінги — переведи крон на щохвилини (з лідом 15 хв пінг тоді прилітатиме
рівно за 15 хв, а не «за 10–15»):

```sql
select cron.schedule('discord-events-sync', '* * * * *', 'select discord_events_sync();');
```

Якщо треба змінити ключ/URL — спочатку `delete from vault.secrets where name in ('discord_events_sync_url','discord_events_api_key');`, потім `vault.create_secret` знову.

> Альтернатива без Vault: Dashboard → **Integrations** → **Cron** → **Create job** →
> тип *Supabase Edge Function*, метод POST, URL функції `/sync`, заголовок
> `x-api-key: <EVENTS_API_KEY>`. Тоді джоб з міграції можна прибрати:
> `select cron.unschedule('discord-events-sync');`.

## Крок 5 (необов'язково). Бот

Бот потрібен для кроку 6 («Події») і щоб закріпити пост (вебхук цього не вміє).
Один бот покриває обидва.

1. https://discord.com/developers/applications → **New Application** → назва.
2. Вкладка **Bot** → **Reset Token** → скопіюй токен (показується один раз).
   Privileged Gateway Intents вмикати не треба.
3. Вкладка **OAuth2** → **URL Generator**: scope `bot`; permissions
   **View Channels**, **Manage Events** (для «Подій») і **Manage Messages** (для
   закріплення). Відкрий згенерований URL і додай бота на сервер.
4. У правах каналу з постом переконайся, що бот бачить канал і має «Керувати повідомленнями».
5. `supabase secrets set DISCORD_BOT_TOKEN="<токен>"`.

Закріплення: функція закріплює пост у момент його створення. Щоб закріпити вже наявний —
закріпи руками, або видали пост у Discord і запусти `sync` (створиться й закріпиться новий).

## Крок 6 (необов'язково). «Події» сервера

Для кожного евента **з часом** на найближчі 7 днів функція створює подію в розділі
**Події** сервера (той, що в меню над списком каналів). Люди тиснуть «Цікавить» і
отримують нативне нагадування Discord на старті. Зміни на сторінці «ДС Евенти» (назва, час,
примітка, тривалість, вимкнення) підтягуються в події за ≤5 хв.

1. Зроби крок 5 (бот з правом **Manage Events**).
2. Скопіюй ID сервера: Режим розробника увімкнений (крок 2.3) → ПКМ по назві сервера →
   **Копіювати ID сервера**.
3. Секрети:
   ```bash
   supabase secrets set \
     DISCORD_GUILD_ID="123456789012345678" \
     DISCORD_EVENT_LOCATION="#евенти"
   ```
   - `DISCORD_EVENT_LOCATION` — текст у полі «місце» події. Discord не вміє
     прив'язати подію до текстового каналу, тому це просто напис (напр. назва каналу,
     де висить пост). Якщо не задати — `Thunder`.
   - `DISCORD_EVENTS_DAYS` — на скільки днів наперед створювати (за замовчуванням 7, максимум 30).
4. Натисни «Оновити зараз» на сторінці або дочекайся крону — у «Подіях» з'являться евенти.

Як це працює:

- Подія створюється одна на евент на дату; у таблиці `discord_scheduled_events`
  зберігається її id і хеш вмісту. Discord смикається лише коли щось змінилось —
  при кроні кожні 5 хв це зазвичай нуль запитів.
- У щоденному пості назва евента з часом стає посиланням на подію, а в пінгу
  посилання йде окремим рядком — Discord показує картку події з кнопкою «Цікаво».
  Посилання має вигляд `https://discord.com/events/<id сервера>/<id події>`.
- Тривалість — поле «триває … хв» у табі (порожньо = 60). Discord вимагає час
  завершення, а після нього сам позначає подію завершеною.
- Коли настає час початку, функція переводить подію в «активна» (на випадок, якщо
  Discord сам цього не зробив).
- Вимкнув евент або прибрав час — подія видаляється. Евент без часу в «Події» не
  потрапляє (Discord вимагає час початку), він лишається тільки в пості.
- Якщо подію видалити руками в Discord — наступний `sync` створить її знову. Не хочеш
  її бачити — вимкни евент на сторінці «ДС Евенти» або прибери час.
- Якщо евент уже почався, час у події більше не змінюється (Discord не дає переносити
  активну подію).

## API

Базовий URL: `https://<ref>.supabase.co/functions/v1/discord-events`.
Авторизація — один із варіантів:

- заголовок `x-api-key: <EVENTS_API_KEY>`;
- `Authorization: Bearer <EVENTS_API_KEY>`;
- `Authorization: Bearer <JWT сесії Supabase>` користувача з таблиці `admins` (так ходить адмінка).

| Метод і шлях | Що повертає |
|---|---|
| `GET /discord-events` | Актуальний список на сьогодні (за Києвом). |
| `GET /discord-events/preview` | Payload, який піде у вебхук (щоб глянути текст поста без відправки). |
| `POST /discord-events/sync` | Оновлює пост (створює, якщо нема), шле пінги, прибирає вчорашні нагадування. |
| `POST /discord-events/test-ping` з тілом `{"eventId": "…"}` | Надсилає пінг евента зараз, поза вікном і позначками; справжній пінг не зачіпає. Те саме робить кнопка «Тест пінгу» біля евента. |
| `POST /discord-events/clean` | Прибирає з каналу всі надіслані пінги, і сьогоднішні теж; пост лишається. Те саме робить кнопка «Почистити пінги» на сторінці «ДС Евенти». |

`GET /discord-events`:

```json
{
  "ok": true,
  "date": "2026-10-10",
  "weekday": 6,
  "weekdayLabel": "Субота",
  "weekdayShort": "Сб",
  "timezone": "Europe/Kyiv",
  "now": "12:40",
  "events": [
    { "id": "…", "name": "ТВ", "time": "20:00", "note": "збір біля Міста Драконів", "durationMinutes": 60, "pingMinutesBefore": 15, "pingRoleId": null, "discordEventUrl": "https://discord.com/events/…/…" },
    { "id": "…", "name": "КХ", "time": null, "note": null, "durationMinutes": null, "pingMinutesBefore": null, "pingRoleId": null, "discordEventUrl": null }
  ]
}
```

Порядок: спочатку евенти з часом (за часом), потім без часу. `time` — `"HH:MM"` або `null`;
`discordEventUrl` — посилання на «Подію» сервера, якщо вона є (крок 6), інакше `null`.

`POST /discord-events/sync`:

```json
{ "ok": true, "date": "2026-10-10", "time": "19:47", "events": 2, "post": "edited", "messageId": "…", "pings": ["ТВ"], "cleaned": 0,
  "scheduled": { "created": 1, "updated": 0, "deleted": 0, "started": 0 }, "warnings": [] }
```

`post` — `created` / `edited` / `unchanged`; `scheduled` — `null`, якщо бот/сервер не
налаштовані (крок 6). Помилка — `{ "ok": false, "error": "…" }` зі статусом 401/405/500/502.

## Як саме працює пост

- **Один пост на весь час.** Перший `sync` створює повідомлення і запам'ятовує його id
  (`discord_event_post`). Далі воно лише редагується — і щодня опівночі (перший крон
  нового дня), і при будь-якій зміні списку. Якщо пост видалити в Discord — наступний
  `sync` створить новий.
- **Discord не смикається даремно:** текст поста хешується, `PATCH` іде лише коли список
  реально змінився.
- **Пінги.** Для евента з часом і «пінг за N хв» у вікні `[час − N; час)` відправляється
  одне повідомлення `@роль ⏰ через N хв — Назва (20:00)`; один пінг на евент на день
  (`discord_event_pings`). Наступного дня ці повідомлення видаляються з каналу, щоб
  там лишався тільки пост; раніше — кнопкою «Почистити пінги» на сторінці (сьогоднішні
  після цього повторно не надсилаються). Пінг без ролі (ні в евенті, ні в
  `DISCORD_PING_ROLE_ID`) — `@here`.
- **Примітка** може бути на кілька рядків і містити посилання: у пості вона йде
  рядками з відступом під евентом, у пінгу — під заголовком, у «Події» — як опис.
  Посилання на канали (`https://discord.com/channels/…`) Discord показує як
  клікабельні згадки каналу, у пості й пінгу також працює markdown (`**жирний**`,
  `[текст](url)`).
- **Картинка** евента (поле «🖼 Картинка: Ctrl+V» поруч із приміткою): скопіюй картинку
  (у Discord — ПКМ → «Копіювати зображення») і натисни в полі Ctrl+V, або перетягни
  файл, або встав посилання. Вставлене зберігається в Storage (бакет `event-images`,
  міграція 0009) — посилання постійне. Показується в пості окремим блоком під
  списком (до 9 картинок), у пінгу під текстом і обкладинкою «Події».
  Посилання `cdn.discordapp.com/attachments/…` спливають за добу — сторінка спробує
  перезалити таку картинку до себе, а не вийде — попередить.
- **«Сьогодні»** всюди за Києвом (`Europe/Kyiv`), як і решта сайту.
- Запити функції до бази рахуються як активність проєкту, тож безкоштовний проєкт із
  працюючим кроном, скоріш за все, не паузитиметься за неактивність.

## Переїзд на інший сервер / канал / роль

Усе міняється через секрети функції (Dashboard → **Edge Functions** → **Secrets** або
`supabase secrets set …`), передеплой не потрібен:

| Що змінити | Секрет | Ще |
|---|---|---|
| Роль для пінгів | `DISCORD_PING_ROLE_ID` | Для окремого евента — поле «роль» на сторінці |
| Канал із постом | `DISCORD_WEBHOOK_URL` (новий вебхук у новому каналі) | Старий пост видали руками; новий створиться сам |
| Текст «місця» / горизонт подій | `DISCORD_EVENT_LOCATION`, `DISCORD_EVENTS_DAYS` | Події оновляться наступним запуском |
| Інший сервер | `DISCORD_WEBHOOK_URL`, `DISCORD_GUILD_ID`, `DISCORD_PING_ROLE_ID` | Запроси бота на новий сервер (крок 5); старі події на старому сервері видали руками |

Функція сама помічає зміну вебхука чи сервера (їх id входять у хеш) і створює новий пост
і нові події. Якщо після зміни все одно «пост без змін» (стара версія функції) — скинь
службовий стан у SQL Editor і натисни «Оновити зараз»:

```sql
delete from discord_event_post;
delete from discord_scheduled_events;
delete from discord_event_pings;
```

## Якщо щось не так

| Симптом | Що перевірити |
|---|---|
| `401 Немає доступу` | Ключ у `x-api-key` ≠ `EVENTS_API_KEY` у секретах; або функцію задеплоєно без `--no-verify-jwt`. |
| `500 DISCORD_WEBHOOK_URL не заданий` | `supabase secrets list` — секрет є? Назва точна? |
| `502 … Discord відповів 401/404` | Вебхук видалили або URL неповний — створи новий (крок 2) і онови секрет. |
